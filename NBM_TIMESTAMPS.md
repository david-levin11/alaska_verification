# NBM percentile timestamp correction

The old pygrib decoder used `validDate` as the endpoint and subtracted the
filename lead to infer initialization. Live operational GRIB samples show that
this property can instead denote the interval start. Both archived timestamps
then become early by the interval duration; the filename forecast hour and
percentile values are not changed by this correction.

The shared NBM/NBMQMD percentile decoder now reads the GRIB reference date/time
and explicit statistical interval endpoint. Instantaneous fields use GRIB
validityDate/validityTime. It rejects inconsistent filename leads and mixed
timestamps among percentile messages. Alaska and Hawaii use the same helper;
experimental products use it too, but have not been live-tested in this change.

Confirmed legacy offsets from operational samples:

| Element | Both timestamps early by |
| --- | ---: |
| MaxT / MinT | 18 hours |
| Precipitation 6 / 24 hours | 6 / 24 hours |
| Alaska snow 6 / 24 / 48 / 72 hours | 6 / 24 / 48 / 72 hours |
| QMD wind, gust, RH | 0 hours |

Snow indexes use annotated `acc@(fcst,dt=...)` labels; the audit now recognizes
these without changing production snow selection.

## Read-only historical inventory

From the repository root, run:

```bash
python assess_archive_timestamps.py --roots model hawaii/model
```

Send the printed JSON report for review. It reports dates, cycle-hour counts,
duplicates, candidate offsets, month crossings, and collisions with existing
keys. It does not modify archives or prove which historical software produced
any row. Correctly scheduled initialization hours alone cannot rule out an
offset, especially for 6/24/48/72-hour fields.

Do not append corrected backfills into affected monthly files before deciding
how to handle their old rows. Corrected keys can coexist with incorrectly dated
ones; de-duplication does not repair this. Preserve backups and provenance.

## GRIB diagnostic

```bash
python audit_nbm_timestamps.py --dates 2026-10-06 --regions alaska hawaii --models nbm nbmqmd
```

`OFFSET` continues to describe the legacy calculation, while
`corrected_matches_metadata` tests the fixed decoder. A nonzero exit is expected
when legacy offsets are found. `NO_MATCH` is not a pass. Downloads and reports
are retained in a unique directory, with no production archive writes.

## Tests with downloaded subsets

```bash
python -m unittest discover -s tests -p 'test_grib_timestamps.py'
```

To additionally run the production station extraction and local Parquet writer
on retained diagnostic subsets, set `NBM_TIMESTAMP_REPORTS` to one or more
comma-separated audit report paths and rerun the command. These tests use
one station per region and temporary Parquet files, write twice to check
idempotence, and verify timestamps against independent GRIB metadata.

## Repair a uniformly legacy local archive

Use `repair_nbm_timestamps.py` only after confirming all selected input months
were generated by the old decoder. A fixed decoder's outputs without repair
markers cannot be reliably recognized from cycle hours alone. Stop production
archive writers before taking the snapshot or running the repair.

```bash
python repair_nbm_timestamps.py \
  --source-root /path/to/model \
  --output-root /path/to/model_timestamp_corrected
```

The output root must be new and outside the input root. The script repairs only
operational `nbmqmd/{maxt,mint,precip6hr,precip24hr}` and
`nbm/{snow6hr,snow24hr,snow48hr,snow72hr}`. Experimental models are intentionally
excluded until their historical provenance and GRIB behavior are confirmed.
Other datasets (including observations, HRRR, RRFS, REFS, wind and RH) are not
copied or modified. Run separately for a Hawaii model root if needed.

It preserves timestamp timezone/dtype and all non-time values, groups output by
corrected UTC initialization month, and verifies exact Parquet round trips,
row conservation, unique forecast keys, source SHA-256 hashes, and a stable
source inventory. It stops on duplicate keys rather than choosing a winner.
Temporary partition files keep memory use approximately monthly rather than
loading the entire archive. Allow disk space for corrected files plus staging.

`manifest.json` records every input/output hash, offset, row count and monthly
routing, with status COMPLETE only after verification. INCOMPLETE outputs must
not be deployed. On failure, investigate and use a new output directory for a
fresh attempt. Marked repaired inputs and existing output roots are refused.
Keep the manifest: later rewrites by other software may strip Parquet markers.

Review the COMPLETE manifest before cutover. Preserve the original affected
dataset directories as backups and replace only those datasets with their
corrected versions. Do not replace the entire model root with this partial
output or overlay old and corrected files. Deploy the fixed decoder before
resuming cron. The optional in-place mode below performs the archive replacement, but does not deploy code or control cron.


## One-command production archive replacement

The operator should use the normal archiving Python environment and account.
Pause cron and wait for any active archiver to finish. Copy the standalone
`repair_nbm_timestamps.py` from this branch onto the server, then run:

```bash
python repair_nbm_timestamps.py --source-root /path/to/model --in-place
```

Wait for the final **INSTALLED** message (not merely the intermediate COMPLETE
message). Original affected datasets are preserved next to the model root in
`model_timestamp_backup_<UTC timestamp>_<id>/originals/`, retaining their model
and element directory structure. Corrected datasets occupy the original paths.
Unrelated datasets stay in place. There is no need to upload the full archive.

Then deploy the fixed code and resume cron. Normal daily appends continue at
the same paths. Do not resume the old decoder against corrected archives.
This branch has not yet been merged into main.

The root-level `timestamp_repair_state.json` records the backup location and
blocks repeat in-place repairs even if later archive writes remove Parquet
metadata. Preserve it and the backup's manifests. The lock protects against
another repair process, not cron; pausing archive writers is required.

Caught installation failures trigger rollback to the original directories.
If the process is forcibly killed or the machine loses power mid-installation,
keep cron paused and use the printed backup directory to recover:

```bash
python repair_nbm_timestamps.py --rollback-backup /path/to/model_timestamp_backup_<id>
```

Recovery refuses a completed installation because new data may have been
appended since then. Inspect the installation journal if any rollback fails;
originals are retained rather than deleted. Have space for corrected copies
and temporary staging in addition to the original archives.
